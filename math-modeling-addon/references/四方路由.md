## 2. 交接物清单（谁交给谁、交什么、缺什么会卡）

### 建模手 → 编程手

交：`题目分析报告.md` + `术语表格.md`（两者 sha256 由编程手自己重算，不抄）。
**编程手可以拒收的三条**：① 目标函数或约束里出现报告未定义的符号 ② 验证判据写成「结果合理」这类不可执行的话 ③ 同一子问里两族模型的适用边界没写清。

### 编程手 → 论文手

交：`results/*.csv` + `figures/*`（SVG + 300 DPI PNG + 灰度） + `results/复现清单.json`。
**论文手可以拒收的三条**：① 图没有题注所需的量纲/口径 ② CSV 里没有可横向对照的列（如灵敏度只给结论不给扫点） ③ 复现清单缺 seed / 容差 / 依赖版本。

### 实测卡点

| # | 卡在哪 | 现行做法 |
|---|---|---|
| D1 | **规范没有「交接切片」模式**：`工作流程.md:41` 要求合同并入 `题目分析报告.md`，`质检清单.md:15` 只认这两个文件 ⇒ 中途只交一小块时无合法出口 | 目录内允许临时切片文件；**不作为交付物、不参与门禁**，在报告里注明「切片，非产物」 |
| D2 | **跨 skill 引用不写路径**：路由原文引 `paper_skeleton.md` / `phrase_bank.md`，两文件其实在 competition-suite 里，论文手照名字找不到 | 跨 skill 引用一律写全 `<skill>/references/...`；并在目标 skill 的 SKILL.md 留反向指针 |
| D3 | **W1/W2 执行者在 subagent 层可能不存在**（本会话 delegation depth = 0） | 由主 Agent 派**同一批**未参与编写的 subagent 判；判不了就记 BLOCKED，不许作者自签 |

## 3. 出图这一段：谁说了算（实测数据，不是偏好）

| 路线 | 耗时 | 必须改动处数 | `figure_audit` |
|---|---|---|---|
| math-modeling `tools/figure` + `plot_style` 自写 | build 12 ms + export 354 ms = **366 ms** | **0** | PASS |
| modelviz 模板 001 环状条形图 | 893 ms | 3（importlib 加载 / 字体 / 数据字典） | FAIL |
| modelviz 模板 005 渐变单因子条形图 | 813 ms（含一次崩溃重跑） | **6** | FAIL |

**四条硬结论**：

1. **默认走 math-modeling 自己的图管线。** modelviz 是**风格参考库**，不是出图管线。
2. **模板不可原地改**：模板末尾 `_stage0_finalize_preview()` 会**删掉模板目录里 data/assets/output 以外的全部文件**。改写一律落 `code/adapted_plot.py`，importlib 按路径加载。
3. **模板默认字体是 Times New Roman + 粗体 ⇒ 中文掉字。** 必须补 `font.sans-serif = ["Times New Roman","SimHei","Microsoft YaHei"]` 与 `axes.unicode_minus=False`；`fix_chinese_font()` 要放在 import 模板**之后**。
4. **audit 绿 ≠ 图能看**（见 §4）。

## 4. 图验收：两轮独立目检才算过

`figure_audit` 只查刻度重叠、长标题、裁切，**不查「任意文字压任意文字」**。所以 audit 之后必须再目检，方法固定：

- 每幅图问四句：① 有没有文字互压/压线/穿字？② 有没有元素被裁或贴边？③ 标注与图例是否指向正确对象？④ 按单栏 3.5 in、正文 7.5 pt 是否可读？
- **判过标准：连续两轮回答「无重叠、无裁切、标注指对」**，一轮不算。
- 看不清就取原图像素复看（3.5 in × 300 dpi ≈ 1050 px，上传降采样后 5.4 pt 小字只剩约 22 px，会假性看不清）。
- **灰度 `_qa` 图不用于位置判断**，只查「颜色编码有没有丢信息」。

实测 audit 全绿之后仍查出的六处：旋转的约束标签压顶点标注｜两个刻度 3 与 4.2 挤糊｜差额标签压住基准值｜图例项与状态标注重叠｜流程箭头横穿同排方框｜斜率说明被竖虚线穿过字头。

## 5. 冲突仲裁

**五级**（高者胜）：官方规则 > math-modeling 交付契约 > scoring-gate 的 verdict > 本文件与 suite 的写法偏好 > modelviz 模板风格。

**四条实测新裁定**（上一版没有，都是撞出来的）：

1. **口径必须显式。** 同一情景换基准窗口能得出 +6400 / −4720 / +1680 三个不同数。凡是「差额」「省了多少」「多花多少」，正文必须写「相对谁」。**这一条该被拦住而没被拦住过一次。**
2. **「预期不可行」记 PASS，不记 FAIL。** 原始 LP 可行域为空是**模型结论**，不是解法失败；但同一段必须写出「所以引入了什么」（本例：引入备货与窗口累计口径）。只写 C1 不写后半句，读者会以为程序错了。
3. **工程参数 ≠ 模型假设。** 会改结论的进 §3 假设并登记；只影响数值精度的叫实现选择，落 `config.py` 并标「实现选择，非模型假设」。**这条判据原规范没给，是编程手现场发明的，现收编为规范。**
4. **产物不会冻结。** 耗时、随机种子、机器相关量，正文只写量级 + 指向产物文件；写死一个数，下一次重跑就变成「文本与产物不符」。实测同一份 `求解参数.csv` 三次重跑给出三套值。

## 6. 反模式（每条都真撞过）

| 这样做 | 后果 | 正确做法 |
|---|---|---|
| 只跑 math-modeling 却声称「按四方流程」 | 另三条腿零贡献，路由变成装饰 | 要么真叫它，要么别写它 |
| 引跨 skill 文件只写文件名 | 下游照名字找不到（D2） | 写全 `<skill>/references/...` |
| 拿 modelviz 成图直接进论文 | audit FAIL、中文掉字、图宽超栏 | 只借配色与构图，重画 |
| 删段落不回头看前向承诺 | 「详见 9.2」指向一个已被删掉的项（W2 P1-5 就是这样） | 删段落时 grep 全文对它的引用 |
| 把「自报页数」当页数 | `--rendered-pages` 是自报值，工具不核 | Word COM `ComputeStatistics(2)` 实测 |
| 用「逐字相同」当唯一可回溯证据 | 呈现层一改（真下标），文本抽取就变（λ_D→λD），证据形态失效 | 证据看「数值/判定/行序」，字面只作辅证 |
| 让作者自己宣布 PASS | 自检看不见自己的漏 | PASS 只能由未参与编写的 subagent 出 |
