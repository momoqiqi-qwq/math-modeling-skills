# 五门禁：谁判、按什么判、评分通道在哪

> 本文件原在 `四方路由.md` §4。移到这里的原因：2026-11-14 端到端验证发现，五个门禁全程由 math-modeling 自己的独立质检 subagent 判定，`mathmodel-scoring-gate` 的 `score_artifact.py` **一次也没被调用**。门禁是 math-modeling 的流程，scoring-gate 是可选的第二意见，不该混写。

## 1. 五个门禁与执行者

| 门禁 | 审的是 | 执行者 | 通过线 |
|---|---|---|---|
| M1 建模终检 | 选型依据、求解可行性、假设可支撑、符号唯一 | 独立质检 subagent（**未参与被审产物编写、只读**） | P0 = 0 且 P1 = 0；有 BLOCKED 需单列 |
| P1 最小可运行结果 | 该子问跑通、结果可追溯 | 同一质检 subagent | 纵向切片跑通；跑不通 → BLOCKED |
| P2 编程终检 | 代码与模型一致、图与数一致、灵敏度真做了 | 同一质检 subagent | P0 = 0 且 P1 = 0 |
| W1 证据大纲 | 结论有出处、章节齐、图表引用闭合 | 同一质检 subagent（**不能是论文手**） | P0 = 0 且 P1 = 0 |
| W2 论文终检 | 误读面、结论强度、假设覆盖 | 同一质检 subagent | 同上 + 页数实测 ≤ 上限 |

**铁律：质检 subagent 不得是被审产物的作者。** 作者自己说「改好了」不算证据——2026-11-14 两次实测都验证了这一点：M1 六轮里 P0 从 4 打到 0，W2 首轮又抓出 6 条 P1，其中一条是作者自己删段落留下的悬空指代，作者复查时没看见。

## 2. 回执固定六段

范围 / 输入快照（每个被审文件的 字节 + sha256 + mtime）/ 状态（PASS｜FAIL｜BLOCKED）/ 证据（每条带 `文件:行号`）/ 发现（P0–P2，每条写「问题—证据—改法」）/ 返工（下轮要看什么）。

**PASS 只能由质检 subagent 出**；作者可以自检，但不能把自检结论写成 PASS。被审产物实质变化后，旧 PASS 立即失效。

### 回执的三条口径要求（实测撞出来的）

1. **段号必须声明口径**：0-based 段序 / 1-based 段序 / `:0094` 风格行号，三种数法差一位。实测同一处改动作者报 `p95`、质检员报 `:0094`，看着差一位，其实是同一段。
2. **改动声明必须说「按什么比」**：按文本比还是按 run 比。真下标化会让「文字逐字未变」的段落 run 结构改变——实测文本口径 17 段变、run 口径 21 段变，两个数都对，只报一个会让复验者怀疑自己数错。
3. **新增/删除段落会使其后段号整体位移**：交付必须自带对齐规则（形如「新件 p0–p178 同号，p179 新增，p180 起 ↔ 旧件 p179 起」），否则复验者按同行号比会误报十几段被改。

## 3. 可选的评分通道（scoring-gate）

需要「一个可复算的分」而不仅是「过/不过」时，才叫 `mathmodel-scoring-gate`：

- 一条命令只带一个 `--stage`，「3 + 4」是跑两次不是一次塞两个。
- 维度权重来自 `config/dim_weights.json[competition][task_type]`，clamp [0.7, 1.5]；`task_type=default` 全 1.0。
- `weighted_mean = Σ(s_i×w_i)/Σ(w_i)`，verdict 七档：`block / pass_early / pass / pass_with_review / refine / refine_partial / carryover`。
- 映射到回执状态（唯一口径）：`block` → BLOCKED；`refine / refine_partial / carryover` → FAIL（列 issue + 下轮 iteration）；`pass_with_review` → PASS 附条件（review_qis 原样抄进「返工」段）；`pass / pass_early` → PASS。

**什么时候值得用**：要给第三方解释「为什么这篇是 7.8 分而不是 8.1」、或同一批多篇要横向排序时。**什么时候不值得**：单篇过门禁——subagent 的回执比加权分更能指出改哪里。
